# حزمة التسليم — تطبيق جوال Bassir BEVIP / Owner Eyes

نسخة الحزمة: 1.0 · التاريخ: 28 أغسطس 2026

---

## 1. نظرة عامة

تطبيق جوال (iOS + Android) لإدارة مشاريع الإنشاءات، يمتد من نظام الويب الحالي **Bassir Owner Eyes**. يخدم أربعة أدوار على نفس قاعدة الكود: **المالك، الاستشاري، المكتب الفني، المقاول**، ويغطي المخططات 2D/3D، جدول الكميات، الجدول الزمني، المستخلصات، التقارير اليومية، الصور الميدانية، وطلبات المعلومات RFI.

الهدف النهائي: نشر التطبيق على **App Store** و **Google Play**، مع خادم يخدم نفس بيانات نظام الويب.

---

## 2. عن ملفات التصميم في هذه الحزمة

الملفات المرفقة `.dc.html` هي **مراجع تصميم مبنية بـ HTML** — نماذج تُظهر الشكل والسلوك المقصود. **ليست كوداً للإنتاج ولا يُنسخ منها مباشرة.**

المطلوب من المطوّر: **إعادة بناء هذه الشاشات في React Native** باستخدام أنماط ومكتبات المشروع، لا تحويل HTML إلى WebView. أي تطبيق مبني على WebView سيُرفض أو يُقيَّم سلباً في مراجعة App Store (القاعدة 4.2 — الحد الأدنى من الوظائف).

### درجة الدقة

**عالية الدقة (hi-fi).** الألوان والخطوط والمسافات ونصف الأقطار نهائية ومذكورة بقيمها الدقيقة في القسم 9. أعد بناء الواجهة بدقة بصرية عالية. النصوص العربية في النماذج نصوص نهائية — استخدمها كما هي.

المحتوى الرقمي (النسب، المبالغ، أسماء المقاولين) بيانات تجريبية توضيحية، تُستبدل ببيانات الـ API.

## 7. متطلبات الـ API

يفترض أن نظام الويب الحالي يوفّرها أو تُضاف إليه. كل الردود JSON، والتوثيق `Authorization: Bearer <token>`.

```
POST   /auth/request-otp          { phone }
POST   /auth/verify-otp           { phone, code } → { token, refreshToken, user, roles }
POST   /auth/refresh              { refreshToken }

GET    /projects/:id/summary      → progress, planned, spend, budget, day, totalDays, kpis[]
GET    /projects/:id/action-items?role=  → قائمة «بانتظار إجراء منك»

GET    /projects/:id/drawings     → [{ id, code, discipline, rev, status, fileUrl, thumbUrl }]
GET    /drawings/:id/file         → PDF (يدعم Range للتنزيل الجزئي)
GET    /projects/:id/models       → [{ id, name, size, glbUrl, lods[], layers[] }]

GET    /projects/:id/boq?contractorId=   → [{ no, description, unit, qty, executedPct }]
GET    /projects/:id/schedule     → [{ id, name, start, end, progress, isCritical }]

GET    /projects/:id/payments     → [{ id, no, contractor, amount, currency, status, history[] }]
POST   /payments/:id/approve      { note? }
POST   /payments/:id/reject       { reason }

GET    /projects/:id/contractors  → [{ id, name, scope, progressPct, username }]
GET    /projects/:id/tech-tasks   → [{ id, title, owner, status, type, dueDate }]
POST   /tech-tasks/:id/decision   { decision: approved|returned, note }

GET    /projects/:id/reports      → [{ id, date, works, crewCount, equipment, weather, status }]
POST   /projects/:id/reports      (multipart، يدعم idempotency-key للمزامنة)
POST   /reports/:id/sign

GET    /projects/:id/photos       → [{ id, url, thumbUrl, title, takenAt, geo, floor, drawingId }]
POST   /projects/:id/photos       (multipart، idempotency-key)

GET    /projects/:id/rfis         → [{ id, code, title, status, assignee, dueDate, drawingPin }]
POST   /projects/:id/rfis
POST   /rfis/:id/reply            { body, attachments[] }

GET    /notifications             → [{ id, type, text, createdAt, read }]
POST   /notifications/read        { ids[] }
POST   /devices/push-token        { token, platform }
```

**متطلبات إضافية على الخادم:**
- تحويل DWG/DXF → PDF للعرض في التطبيق.
- تحويل IFC → GLB مضغوط بعدّة مستويات LOD.
- توليد مصغّرات للوحات والصور.
- `idempotency-key` على كل POST يأتي من طابور المزامنة لمنع التكرار.
- ترقيم الصفحات (`?page=&limit=`) على كل القوائم.

## 8. العمل دون اتصال

1. **قراءة:** تُخزَّن آخر نسخة من الملخص والقوائم في SQLite وتُعرض فوراً، مع إعادة الجلب في الخلفية.
2. **اللوحات:** المستخدم يختار «تنزيل للعمل دون اتصال»؛ تُنزَّل ملفات PDF ومصغّرات إلى نظام الملفات. سقف افتراضي 1.2GB مع إدارة من الملف الشخصي.
3. **كتابة:** التقارير والصور و RFI تُحفظ محلياً بحالة `pending` وتظهر في القائمة بعلامة انتظار، ثم تُرفع تلقائياً عند توفر الشبكة (`expo-task-manager` + `NetInfo`)، مع إعادة محاولة تصاعدية (1د، 5د، 15د، ساعة).
4. **التعارض:** الخادم هو المرجع. عند رفض عنصر مؤجل يظهر إشعار بالسبب ويبقى العنصر محلياً للتعديل.
